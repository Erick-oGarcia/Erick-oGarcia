### 🔬 Featured: [toolshop-quality-harness](https://github.com/Erick-oGarcia/toolshop-quality-harness)

[![CI](https://github.com/Erick-oGarcia/toolshop-quality-harness/actions/workflows/pr.yml/badge.svg)](https://github.com/Erick-oGarcia/toolshop-quality-harness/actions/workflows/pr.yml)

A full-stack quality harness for a real e-commerce app, self-hosted with Docker Compose. UI, API and **database checks** live in the same Playwright/TypeScript suite.

* 🗄️ **The database as an independent source of truth.** Most suites only ask the application. When the application is wrong, they agree with it — the API returned `200` for products that no longer existed in the database, and neither a UI nor an API test would catch it.
* 🔴 **Every check is shown failing before it is trusted.** A check that has never been seen red is not evidence of anything.
* ⚡ **A performance gate that survives a shared runner.** The k6 budget is derived from the same machine in the same run, so it works on my laptop and on a CI runner without retuning.
* 🤝 **A consumer-driven contract, not a snapshot.** The Pact contract demands only the five fields the client actually reads, so the provider stays free to change the rest.
